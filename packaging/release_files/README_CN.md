# U-Arm → Dobot CR5AF + DM4310 夹爪遥操 v0.1.0

这是 Windows x64 离线交付包，包含当前项目实际使用的遥操源码、标定配置、U-Arm/CR5/夹爪模型、T-CAN485 网关固件、测试和依赖。为避免部分 Windows 解压软件造成中文文件名乱码，交付包的全部文件名采用 ASCII；中文说明保留在本文件中。主入口是 `START_TELEOP.bat`。

## 一键使用

1. 解压到本机普通目录，路径可以包含中文，但不要直接在 ZIP 内运行。
2. 双击 `INSTALL.bat`。它使用包内 Python 3.13.9 安装器和 wheels，在本目录创建 `.python`/`.venv`，不修改系统 PATH。
3. 双击 `READONLY_DIAGNOSTICS.bat`，确认 FE-URT-2 串口可见，且 `192.168.201.1` 的 29999、30004、60000 端口符合现场状态。
4. 双击 `START_TELEOP.bat`。打开面板不会使能机器人；只有在面板中明确启动后，真机才会动作。
5. 需要双臂/夹爪 3D 监视时，双击 `START_SIMULATION.bat`。

换电脑或更换 URT-2 后，先编辑 `config/device_connection.json`：`robot_host` 填控制器 IPv4 地址，`leader_port` 填设备管理器中确认属于主臂的端口（例如 `COM12`）。`auto` 只在检测到唯一一个 VID:PID `1A86:55D3` 的 CH343 适配器时生效；同时存在多块同型号适配器时必须明确填写 COM 口。机器人 IP 和主臂串口会传入遥操控制、回零恢复及仿真入口。

仿真入口读取硬件反馈；只想离线验证模型时，安装器的模型自检即可，无需连接机器人。独立仿真与遥操同时争用主臂串口可能冲突，遥操运行时请使用面板内“打开 3D 实测监视”。

## 硬件基线

- Windows x64；有线网卡地址与机器人同网段。
- Dobot CR5AF / CC262：`192.168.201.1`，DobotStudio Pro 置于 TCP 控制模式。
- U-Arm：FE-URT-2 通过 USB 接入；程序按 CH343 VID/PID 自动寻找唯一适配器，不固定 COM 号。
- 夹爪链路：PC → CR5AF/CC262 → 末端 RS485 → T-CAN485 → Classic CAN → DM-J4310-2EC V1.2。
- 当前控制软件通过 `192.168.201.1:60000` 访问已刷入受保护固件的 T-CAN485；运行遥操时不使用网关 USB 串口。
- 末端 RS485 采用 115200、8N1；CAN 采用 1 Mbps，电机 ID=1。`src/configure_tool485.py` 会修改末端参数，安装器不自动运行它。USB 驱动、现场 IP、控制器 TCP 模式和网关固件需与这套硬件相符；离线软件包不能自动完成新设备的物理接线和标定。

## 当前标定与适用边界

包内保留了本机已经实测的六轴方向、J2 比例、接管姿态逻辑、ID7 扳机端点和 DM4310 开闭端点。它可以在同一套硬件上直接复现，但更换 U-Arm 舵机、机械结构、夹爪、电机零位、控制柜或固件后，必须重新核对标定；不要把本包端点当成另一套设备的通用参数。

控制面板仍保留关节限位、速度上限、跟随误差、反馈超时、急停/报警检查和停止清理。软件停止不等于实体急停。首次交付复现必须低速、空载、清空区域，并让实体急停随手可及。

## 文件结构

- `src/`：全部 Python 控制、诊断、标定与仿真程序。
- `config/`：当前实测标定和界面参数。
- `simulation/generated/`：实际加载的已修复 U-Arm、CR5 和夹爪模型。
- `models/source/`：模型原始来源的精选副本及许可文件。
- `official/`：运行时需要的 Dobot 与 PathOn Robotics 模型资源。
- `firmware/`：T-CAN485 源码；`tcan485_dm4310_read_probe/prebuilt/firmware.bin` 是已实机验证版本。
- `tests/`：主机控制、夹爪状态机、仿真映射和生产 C++ 逻辑测试。
- `docs/`：审计、标定和修复证据文档。
- `SHA256SUMS.txt`：除自身外所有交付文件的 SHA-256。
- `THIRD_PARTY_NOTICES.md`：包内运行时、wheels、模型及上游资源的许可来源说明。

原始 Config2 模型目录中的 4 个中文 3MF 文件为避免跨解压器乱码，交付时只改文件名、不改内容：`中间4个.gcode.3mf` → `middle_4.gcode.3mf`，`前4个.gcode.3mf` → `front_4.gcode.3mf`，`立柱.gcode.3mf` → `pillar.gcode.3mf`，`立柱和扳机.gcode.3mf` → `pillar_and_trigger.gcode.3mf`。其 SHA-256 由总清单记录。

## 安全停止和报警恢复

- 正常停止：先点面板“停止并失能”，等待结束状态；不要直接拔网线。
- 失控、碰撞风险或程序无响应：立即按实体急停，之后再排查软件。
- CR5 报警：先解除真实碰撞/限位/接线原因，再按现场批准的恢复流程清警和回安全位。不要用脚本盲目重复清警或回零。
- 夹爪夹到物体时允许低力保持；通信丢失、温度/故障异常或网关硬件保护才应停止。更换夹爪后需重新标定端点。

## 验证

`RUN_OFFLINE_TESTS.bat` 不驱动硬件。包内安装结束也只做导入和文件完整性检查，不访问串口、网络或真机。

`scripts/verify_integrity.py` 校验清单列出的发布文件。运行后修改过标定或重新生成过模型，校验会如实报告文件已变化。C++ 固件逻辑测试需要本机 C++ 编译器或现有 WSL 环境；无编译器时这两项会标记为跳过，不能视为已运行。

此次已验证本机现有 Python 3.13 下的新建虚拟环境离线安装；尚未在完全未安装 Python 的独立 Windows 系统上验收内置安装器分支。内置安装器签名、哈希已检查。

## 固件与历史资料

当前网关固件为 4.6。包内 esptool 支持受保护上传器写入已配置 T-CAN485 的应用区，仍需明确指定刷写参数并通过原有预检；打开面板或安装不会刷固件。全新空白板缺少引导、分区或网络状态时不能使用该升级流程，需要单独调试，详见固件 README。

重新编译固件源码需要另行准备 PlatformIO 及 `espressif32@6.11.0` / Arduino 工具链（不在本包内）。`docs/` 和 `README_PROJECT.md` 保留了不同开发阶段的历史记录，其中的旧版本、日志路径和“尚未验证”结论不是当前运行步骤；当前交付步骤以本文件和 4.6 固件说明为准。`models/source` 内 CR10/Isaac/ROS 示例是上游参考，不是本包一键安装的 CR5 MuJoCo 运行入口。
